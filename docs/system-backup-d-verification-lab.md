# D 独立校验演示

此入口在本机调用 A 的 `systembackupbusinessa.VerifyBackupSnapshot`，复用管理页的任务表格、校验详情、报告接收校验和下载表单。任务、检查项和报告来自每次真实函数调用，没有预写成功结果，也不改数据库。

输入是合成快照；注册审批和捕获证明为进程内测试夹具。这只演示 A 的快照完整性检查逻辑，不连接现场数据库、B 的证书或 C 的 provider，不是备份可用性或恢复验收。详情始终保留可用性未知/待验证，不因检查通过改成可恢复。

## 启动

前提：Windows PowerShell、已有 Go 1.26.1 工具链及 Go 模块缓存、已有 `frontend/node_modules`。无需数据库、业务账号、密码、TOTP、生产开关或现场 SQL。脚本禁止下载 Go 模块或工具链，不安装依赖，缺失时直接报错。

在仓库根目录运行：

```powershell
.\scripts\system-backup-d-verification-lab.ps1
```

等待终端提示后，打开 [独立测试页面](http://127.0.0.1:19032/verification-lab.html)。端口 19031/19032 必须空闲。服务仅监听 `127.0.0.1`，与正常 9001/9002 页面和 API 分离，无需登录。前端入口不加入生产构建或路由。

## 固定演示步骤

1. **准备数据**：选择“数据一致”，点击“准备数据”，确认显示 `match`。此时没有成功任务或报告。
2. **执行**：点击“执行校验”，观察运行提示及自动刷新的列表。一次准备只允许消费一次，重复执行会被服务端拒绝。
3. **结果**：任务结束为成功，自动打开详情。检查汇总为 20 项通过；下方表格展示 A 返回的检查 ID、状态、预期及实际值。
4. **报告**：在详情报告表单点击下载，确认文件大小与 SHA-256 后点击保存。客户端复用原有长度、摘要、附件接收校验，并核对详情引用的摘要。报告包含任务 ID、场景、A 检查原结果、失败类别、完成时间及测试范围。
5. **反例**：选择“行数不一致”，重新准备、执行，结果为失败，其中 1 项行数检查失败，其余 19 项通过。下载报告可定位 `ai_gateway.table_count.audit_events`。
6. **缺证明**：选择“缺少捕获证明”，重新准备、执行，结果为失败，类别 `evidence_incomplete`，A 不返回检查项；报告仍可下载，不伪造通过项。
7. **重置**：点击“重置演示”，任务、准备数据和报告全部清空；旧报告 URL 返回 404。运行中也可重置，旧任务迟到结果不会重新出现。再次从第 1 步开始即可由另一位同事重复演示。
8. **停止**：终端按 Ctrl+C；脚本停止本次两个服务，删除本次二进制、Go 构建缓存、Vite 缓存和日志。手动保存的报告由演示人员按需要保留或删除。

每个进程最多保留 20 次结果，达到上限后重置再执行。刷新浏览器可重新查看进程内任务；重启服务清空全部数据。此入口不收集业务凭据，请勿输入真实密码。

## 故障恢复

页面连接失败时检查启动终端，点击“刷新状态”。提交执行时断网不要盲目重复执行，刷新后查看任务是否已创建；同一准备 ID 无法重复消费。准备失败或场景选错时重新准备即可；执行始终使用页面提示的已准备场景。报告被重置或摘要不一致时下载失败，不能保存不完整文件。

固定流程只依赖仓库源码和本机已有依赖。当前没有把本机夹具结果登记到生产任务表；现场安装的端到端验收仍需 A/B/C 的真实捕获证明、数据源、provider 和现有鉴权运行时。

可用 `./scripts/system-backup-d-verification-lab.ps1 -Smoke` 自动执行同一启动流程、三种场景、公共读取合同解析、报告摘要校验及重置检查，退出后自动清理临时产物；此模式不替代浏览器点击验证。
