| report/journal 持久卷 | PVC→PV→CSI/volumeHandle/实际存储后端、Pod UID/挂载、实际 Unix 所有者/模式、空间预算、报告原子替换/可见延迟 | 名称不同不证明物理隔离；journal 0600/0640、实际单写者与独立预留空间需现场验收。ReadWriteOncePod/fsGroup 字段本身不能证明挂载事实。 |
| DDL/完整元数据 | 特权观察者的表/列/FK/index/CHECK/trigger/program 原始清单与 pin、变更冻结机制及当前撤权 | 比较完整集合，不能只按可见数量相等放行；完整 GC 和正式共享 schema/角色尚未批准。 |

这些公共输入已有[离线组合器及模板](system-backup-a-download-k8s-composition-20261020.md)，不再另造一套配置格式。组合输出仍为零副本 Deployment、暂停 Job；只有实际材料、角色、容量、存储和 E2E 门禁齐全后才进入部署决策。本轮不更改其状态。

## 4. 验收顺序和责任边界

A 先接 owner 十一项，再接角色十项与扩展组件所需真实权限/锁证据，随后接上表中的实际材料、物理容量和运行卷；完整 policy、正式共享 schema/角色、本人 MFA/provider 和恢复矩阵 E2E 继续按原分工推进。D 的新 task/producer 专项由它们自己的准确根、同轮源码和清理回执接收，避免同时重复发起。

当源码仍在编辑时，A 可继续读不可变日志、审准确查询、整理原始材料和角色差异；不要以增加快照重试次数、关闭 hash 守卫、跳过 vet 或反复执行已通过的本地套件来替代现场证据。
